## 0. エグゼクティブサマリー

### 提案タイトル

EEG・作業文脈・操作ログによるナレッジワーカーの集中最適化ポモドーロシステム

### チーム概要

Sigre AI は，東京農工大学の学生プロジェクトで脳波計測デバイス，電極，装着筐体，BLE 計測アプリ，解析サーバを試作してきたメンバーを中心とするチームである．工学院大学の近藤蒼大氏と連携し，耳介周辺電極，日常環境での EEG 計測，SSVEP-BCI，信号品質評価の知見を取り入れる．

### ソリューション概要

本提案は，消費者向け EEG，作業ツールの API/SDK，画面解析，操作ログを組み合わせ，25 分単位の知的作業における集中の質，認知負荷の上昇場面，進捗停止場面を可視化するポモドーロシステムである．

初期実装では，VS Code や Notion 等の拡張機能を通じて作業内容を取得し，API/SDK で取得できない画面情報を VLM/OCR で補完する．作業後には，認知負荷，操作量，成果物差分を同じ時間軸に沿って整理したレポートを生成し，次回の Todo をより小さく実行しやすい単位へ更新する．

将来的には，個人向けアプリに加え，企業の開発・研究・企画部門で利用する B2B ライセンス，既存タスク管理ツールとの連携 SDK，互換ハードウェア向けの仕様公開を通じて，集中最適化エコシステムを形成する．

### コメントへの回答

- B2C と B2B の両方で展開できる点を，個人向けアプリ，企業向けライセンス，既存ツール連携 SDK，互換ハードウェアという形で本文に反映した．
- 「ソフトを一式自作する」だけではなく，VS Code/Notion 拡張や外部サービスに接続できる SDK/ハードウェア連携を将来展開として明示した．
- 公開サマリーでは秘匿情報を避けつつ，作業者にとっての価値が伝わるよう，最小構成を「作業内容取得，画面補完，作業後レポート，Todo 更新」に絞った．

### 課題・背景

ナレッジワーカーは，作業停滞の原因を自分だけでは正確に把握しにくい．「今日は集中できなかった」「作業が進まなかった」と感じても，その原因は，通知による中断，タスクの難しさ，過負荷，眠気，単なる操作停止，深い思考などに分かれる．行動ログは操作や画面上の出来事を記録できるが，その背後の認知状態までは直接示せない．

本提案は，認知状態の推定を本人の主観や行動ログだけに頼らず，EEG から得られる課題関与・認知負荷指標で補完する．この補完により，同じ「手が止まった」状態を，高負荷での停滞，低負荷での離脱，深い思考の継続に分け，次の作業計画へ反映する．

## II. 審査用資料

## 1. 懸賞広告との合致性

本提案は，テーマ 1「パフォーマンス最適化ソリューション開発」に合致する．

- ゼロからプラス: 集中しやすい作業順序とタスク粒度を提示し，アウトプット品質と単位時間あたりの処理能力を高める．
- マイナスからゼロ: 過負荷，注意逸脱，中断，タスク粒度の不一致による手詰まり時間を減らす．
- キーワード対応: パフォーマンス向上，心身の疲労低減，自己理解・自己実現支援に対応する．

本チャレンジは，脳由来信号を活用して新しい市場や体験を創出することを求めている．本提案は，従来の集中タイマーや行動ログツールでは扱えなかった認知負荷の変化を EEG で捉え，作業文脈と結びつけてレポート化し，次回 Todo の設計へ接続する点で，技術課題と社会課題の双方に資する．

## 2. 提案ソリューションの革新性

本提案の革新性は，脳由来信号を単なる集中スコアとして表示せず，実際の作業文脈と統合し，次の作業設計に接続する点にある．

既存のウェルネス系ニューロテックは，瞑想，睡眠，音楽聴取など，作業から切り離された場面を主な利用シーンとしている．本提案は，既存サービスを否定せず，コーディング，文書作成，研究，設計，企画といった日常的な知的作業そのものを対象にする．

システムは，EEG，操作ログ，作業ツール連携，画面解析を組み合わせる．VLM は画像や画面を解釈する AI であり，API/SDK から取得できない画面上の文脈を補完する．初期 PoC では，VS Code や Notion 等の拡張機能で取得できる構造化情報を優先し，画面録画と VLM/OCR は構造化情報だけでは不足する文脈の補助に用いる．

この構成により，低い集中度だけを示す画面ではなく，「特定のエラー解消で高負荷が続いた」「資料検索中に操作は少ないが課題関与は維持されていた」「通知前から課題関与が低下していた」など，作業改善に使える説明を提供する．

### コメントへの回答

- 既存ニューロテックを批判せず，「瞑想，睡眠，音楽聴取など作業から切り離された場面が中心」と整理し，本提案は日常的な知的作業そのものを対象にする，という差別化にした．
- VLM は冒頭で「画像や画面を解釈する AI」と説明し，審査側が前提知識なしに読めるようにした．
- VLM/OCR を前面に出しすぎると開発負荷が重く見えるため，API/SDK で取れる構造化情報を主，画面解析を補助とする構成へ本文を修正した．

## 3. 新市場創出効果

### ターゲットとペイン

初期ターゲットは，ソフトウェアエンジニア，研究者，デザイナー，コンサルタントなど，PC 上で複雑な知的作業に従事するナレッジワーカーである．初期 PoC では，対象を開発職又は研究開発職に絞り，VS Code や Notion などの拡張容易なツールから検証する．

表層ペインは，「集中できず仕事が終わらない」「時間の使途が分からない」「頑張ったのに進捗が出ない」といった主観的な停滞感である．構造的ペインは，認知状態が本人にも見えず，行動ログだけでは作業停止の原因を区別できない点にある．根源ペインは，人間が自分の認知負荷や課題関与をリアルタイムに正確にモニタリングできないことである．

本提案は，この見えない認知状態を，EEG と作業文脈の同期記録によって可視化し，次回の作業設計に反映する．

### SAM の考え方

5 年後の SAM は，自社の売上のみではなく，「認知状態に基づく集中最適化」の価値を提供するエコシステム全体の市場として定義する．対象には，自社ソフトウェア，自社又は提携ハードウェア，互換ハードウェア，既存タスク管理ツールやコミュニケーションツールへの拡張機能を含める．この定義により，自社単独の売上規模ではなく，互換ハードウェアや既存業務ツール拡張を含む市場形成効果として 1,000 億円規模を説明する．

市場形成の経路は次の通りである．

- 自社ソフトウェア: 個人向け月額課金，企業向けライセンス，開発・研究部門向けの生産性改善ツールとして展開する．
- 自社ハードウェア: 検証済み EEG デバイス又は推奨デバイスを提供し，初期ユーザに安定した計測体験を届ける．
- 互換ハードウェア: 計測仕様や連携インタフェースの一部を公開し，他社 EEG デバイスや耳介周辺電極デバイスを本ソフトウェアへ接続する．
- 既存ツール連携: Slack，Microsoft Teams，Jira，Confluence，Notion，Microsoft 365，VS Code 等の API/SDK と連携し，通知，中断，成果物更新，タスク状態を認知状態と結びつける．

自社だけで 1,000 億円規模の売上を達成する前提ではなく，集中最適化に関わる互換デバイス，作業文脈解析，タスク管理拡張，企業導入を含む市場全体を創出する．初期 SOM は，国内の IT 技術者・研究者など約 150 万人を対象母集団とし，月額 2,000 円程度のソフトウェア価値とハードウェア買い切りを組み合わせて検証する．

### アウトカム

アウトプットは，作業レポート，状態区間の可視化，Todo 更新案である．アウトカムは，それらを利用した結果として生じる作業成果と利用者価値である．この区別により，レポート生成そのものではなく，作業効率，作業品質，主観的負荷，Todo 実行率を評価対象にする．

- 校正・レビュータスクにおけるエラー検出率の向上
- タスク完了時間又は同一時間内の完了件数の改善
- コンテキストスイッチ回数と手詰まり時間の低減
- NASA-TLX や VAS による主観的負荷・疲労感の低減
- システムが提案した小タスクの受諾率・完了率の向上
- 企業利用では，納期遅延，レビュー戻り，過負荷状態の継続を減らすことによる生産性改善

### コメントへの回答

- 5 年後 SAM 1,000 億円は自社単独売上ではなく，集中最適化エコシステム全体の市場として定義した．自社ソフト，自社又は提携ハード，互換ハード，既存ツール拡張，企業導入を含める．
- SaMD や医療機器としての訴求は外し，作業支援，セルフモニタリング，パフォーマンス最適化として位置づけた．
- B2C 単体に絞らず，B2B ライセンスと既存業務ツール連携を含めた．一方で，初期 SOM は国内 IT 技術者・研究者等に絞り，PoC の検証範囲を狭めた．
- ペインは「集中できず仕事が終わらない」だけでなく，認知状態が本人にも行動ログにも見えず，操作停止の原因を区別できないこととして定義した．
- アウトプットとアウトカムを分け，レポート生成そのものではなく，タスク完了時間，エラー検出率，主観的負荷，Todo 受諾率・完了率を購買価値に接続した．

## 5. 脳由来信号の科学的妥当性

本提案で扱う主な脳由来信号は，頭皮上電極で非侵襲に取得する EEG であり，ルールブック上の脳情報に該当する．

計測系は，自作 ADS1299 系デバイスに加え，SEEG100E 等の検査済み計測系と比較評価する．SEEG100E は，外来ノイズへの強靭性，入力インピーダンス，CMRR 等の計測信頼性を説明する上で有用なため，非人体評価と人体評価の双方で基準計測系として用いる．

解析では，0.5 から 30 Hz のバンドパスフィルタと 50 Hz ノッチフィルタを事前に定めて適用する．theta，alpha，beta 帯域のパワーを用いるが，顔や首の筋活動，まばたき，眼球運動，体動，電極接触不良が大きい区間では認知状態指標を更新しない．特に 20 から 30 Hz 付近に残る筋電成分を beta 帯域の課題関与と誤認しないよう，除外区間，除外電極，除外理由を保存する．

主な指標は次の通りである．

- 課題関与: beta / (alpha + theta)
- 認知負荷: 前頭 theta パワー，前頭 theta と頭頂 alpha の対数差
- 低覚醒・疲労方向: (theta + alpha) / beta
- 探索的指標: 前頭 alpha 非対称性，前頭部・頭頂部間の dPLI

各指標は，先行研究で報告された集団傾向をそのまま個人へ当てはめず，安静，単純作業，N-back，PVT，実作業ブロックを用いて本人内の基準値，日内変動，日をまたぐ再現性を確認する．

### コメントへの回答

- SEEG100E 等の検査済み計測系を，人体評価と非人体評価の双方で基準計測系として使う方針にした．外来ノイズへの強靭性，入力インピーダンス，CMRR などは，検査済み計測系との比較に基づいて説明する．
- 「脳波らしいものが取れる」だけでは弱いため，帯域別 PSD，閉眼 alpha，SSVEP，N-back 中の theta 変化を事前評価に入れた．
- 感情価や dPLI は主判定にせず探索的指標に下げ，短期 PoC では認知負荷，課題関与，低覚醒・疲労方向を中心にした．
- 筋電，瞬目，眼球運動，体動，電極接触不良が大きい区間では認知状態指標を更新しない，という除外方針を本文に入れた．

## 6. 研究開発計画の信頼性

NEDO 期間内の開発は，実現可能性を重視して段階化する．初期 PoC は全ツール対応や完全な自動スケジューリングを狙わず，センシング，作業レポート，Todo 更新の有効性検証に集中する．

### Month 1: 同期記録基盤

EEG，操作ログ，作業ツール API/SDK，指定ウィンドウの画面録画を共通時刻へ同期する．初期対象ツールは，VS Code 又は Notion など，拡張機能と API が整っているものに絞る．画面録画と VLM/OCR は，API だけでは不足する画面文脈を補完する．

### Month 2-3: 状態推定と計測品質評価

SEEG100E 等の基準計測系と自作計測系を比較し，帯域別 PSD，閉眼 alpha，SSVEP，N-back 中の theta 変化を確認する．認知負荷と操作量を組み合わせ，作業状態を「順調な集中」「高負荷な集中」「高負荷で停滞」「低活動だが思考中」「作業からの離脱」に分類する．

### Month 4: 作業レポートと Todo 更新

25 分ブロックごとに，認知負荷，課題関与，操作量，成果物差分，画面文脈を同じ時間軸で確認できるレポートを実装する．高負荷で停滞した場合は，次回 Todo をより小さな最初の一手へ分解する．低活動だが思考中の場合は介入せず，低負荷で離脱している場合は休憩又は低負荷タスクへの切替を提案する．

### Month 5-6: PoC 評価

ナレッジワーカーを対象に，被験者内比較を実施する．条件は，介入なし，作業レポートあり，作業レポートと Todo 更新ありの 3 条件を基本とする．評価指標は，タスク完了時間，エラー検出率，コンテキストスイッチ回数，NASA-TLX，VAS，Todo 受諾率・完了率とする．

### コメントへの回答

- 研究開発計画は，II. 審査用資料を正として Month 1 から Month 5-6 の段階計画に統一した．III. 補足資料の実施計画もこの順序に合わせる．
- P10 の性能指標を評価へ使うというコメントに沿って，タスク完了時間，エラー検出率，コンテキストスイッチ回数を主要アウトカムに入れ，NASA-TLX と VAS も主観的だが定量評価として採用した．
- NEDO 期間内は全閉ループの自動スケジューリングではなく，同期記録，状態推定，作業レポート，Todo 更新，PoC 評価に限定した．

## III. 審査用補足資料

## 1. 課題・背景

ナレッジワーカーが高い生産性を維持するためには，集中力を管理するだけでなく，集中が切れる要因や過負荷になる作業条件を把握し，次の作業設計へ反映する必要がある．集中力の変化には，通知やアプリ切替による中断，タスク難度による認知負荷，睡眠不足や疲労などの身体状態，作業環境が関与する．

しかし，従来のポモドーロタイマーや行動ログツールは，作業時間，アプリ利用時間，操作量を記録するにとどまり，ユーザの実際の認知状態を扱わない．行動ログ上は同じ「操作停止」でも，高負荷で問題を解こうとしている場合，低負荷で注意が逸れている場合，深く考えている場合では，必要な支援が異なる．

本提案は，EEG から課題関与と認知負荷の指標を算出し，作業ツールの API/SDK，画面解析，操作ログ，Todo，成果物差分と同期して記録する．この同期記録により，集中や認知負荷が変化した区間を検出し，その区間の作業内容，操作停止，成果物変化を作業文脈と結びつけて説明する．

提案システムは，認知タスクにおける Apple Watch のような存在を目指す．すなわち，身体活動や心拍を用いて生活行動を振り返るように，EEG と作業ログを用いて知的作業の負荷，停滞，中断，回復を振り返り，次の作業計画を改善する．ただし NEDO 期間内では，検証可能性を優先し，最初から全自動の計画生成や広範なツール連携を実装対象にしない．

NEDO 期間内では，計測・可視化・レポート・次回 Todo 更新に絞って検証する．将来的には，PC を開いた時点で，その人の集中しやすい時間帯，直近の疲労傾向，タスク負荷に応じて，その日の作業順序を提案するシステムへ発展させる．

### コメントへの回答

- 「認知タスクにおける Apple Watch」の比喩は，知的作業の負荷，停滞，中断，回復を振り返るシステムとして本文に取り込んだ．
- ただし，NEDO 期間内に実現できるか不透明な全自動計画生成は発展計画へ下げ，申請書本文では計測，可視化，レポート，次回 Todo 更新を検証範囲とした．
- 背景説明は，集中力一般ではなく，操作停止の意味が行動ログだけでは分からないという本提案固有の課題へ寄せた．

## 2. ソリューション概要・アウトカムの説明

### ソリューション概要

本提案のシステムは，25 分の作業ブロックを単位として，EEG，作業ツール連携，画面文脈，操作ログ，Todo，成果物差分を同期記録する．中心機能は，作業後の振り返りレポートと，認知負荷に応じた Todo の細分化である．

初期実装では，VS Code や Notion など，拡張機能や API/SDK を通じて作業内容を取得しやすいツールを対象とする．これにより，ファイル変更，編集中の文書，タスク状態，エラー発生，コミットや更新履歴を構造化データとして取得する．VLM/OCR は，構造化データだけでは把握できない画面上の情報や，ユーザが指定したウィンドウ内の作業文脈を補助的に解釈する．

EEG は，行動ログでは分からない認知負荷と課題関与の変化を捉える．操作量が低い場合でも，EEG が高負荷を示せば「詰まっている可能性」，EEG が適正負荷を示せば「深い思考中の可能性」，低負荷を示せば「注意逸脱又は作業離脱の可能性」として区別する．この区別により，操作停止時に常に介入するのではなく，深い思考を保護しながら必要な場面だけ支援する．

作業後には，状態変化が起きた区間，その時点の画面・ツール文脈，成果物差分，判定理由をまとめたレポートを生成する．さらに，認知負荷が高く停滞したタスクは小さな実行単位へ分解し，ユーザの承認後に次回 Todo へ反映する．

### アウトカム

本提案におけるアウトプットは，状態可視化，作業レポート，Todo 更新案である．アウトカムは，これらを用いた結果として生じる，ユーザの作業成果と購買価値である．

- 作業効率: タスク完了時間の短縮，同一時間内の処理件数増加
- 作業品質: 校正・レビュータスクのエラー検出率向上，手戻り減少
- 認知負荷: NASA-TLX，VAS による主観的負荷・疲労感の低減
- 実行可能性: 提案 Todo の受諾率，完了率，次回着手率の向上
- 組織価値: 中断要因や過負荷要因の可視化によるチームの作業設計改善

### コメントへの回答

- SDK/API が豊富なツールを 1 から 2 個選ぶ方針に修正した．初期候補は VS Code 又は Notion とし，Jira，Confluence，Microsoft 365 などは拡張候補に置いた．
- OCR/VLM だけで作業理解する構成から，対象ツールの構造化情報を主にし，不足部分を VLM/OCR で補助する構成へ変えた．
- 「生成レポート」はアウトプットであり，アウトカムではないという指摘に対応し，作業レポート，状態可視化，Todo 更新案をアウトプット，作業効率，作業品質，主観的負荷，実行可能性をアウトカムとして分けた．
- EEG は 3 か月だけ測って捨てる較正データではなく，行動ログの意味を継続的に個人内で解釈する中核信号として維持した．

## 3. ソリューションの革新性

本提案の新規性は，EEG を日常の知的作業と直接結びつける点にある．従来のニューロテックは，瞑想，睡眠，音楽聴取など，作業そのものから独立したウェルネス利用が中心であった．本提案は，この既存領域と異なり，ユーザが実際に進めている開発，執筆，調査，企画，レビューの文脈で認知状態を扱う．

行動ログだけでは，操作停止の意味を区別できない．EEG を組み合わせることで，同じ操作停止でも，過負荷による停滞，低覚醒による離脱，深い思考，単なるツール待機を区別する手掛かりが得られる．この役割があるため，本提案では EEG を短期の較正用データではなく，作業ログの意味を個人ごとに解釈する中核信号として扱う．

また，Jira，Confluence，Notion，Microsoft 365，VS Code などの既存ツール連携を前提とするため，作業文脈を無理に全て画面 OCR で読み取る必要はない．API/SDK で取得できる構造化情報を主とし，VLM/OCR を補助として用いることで，開発負荷を抑えつつ，実作業に近い評価が可能になる．初期 PoC では，この方針に沿って 1 から 2 種類の対象ツールへ絞る．

本提案は，状態変化を抽象的な集中度として示すだけでなく，特定のエラー解消，資料検索，通知，中断，成果物更新の停滞といった作業内容に結びつけて説明する．さらに，過負荷で停滞したタスクを小さな実行単位へ分解し，ユーザの承認後に次回 Todo と作業計画を更新する．

### コメントへの回答

- ウェルネス用途との差分は，既存サービスを否定せず，開発，執筆，調査，企画，レビューのような実作業文脈で EEG を使う点として表現した．
- Jira，Confluence，Notion，Microsoft 365，VS Code 等の既存ツール連携を本文に入れたが，PoC では 1 から 2 ツールに絞ると明記した．
- 「脳波はいらないのでは」という懸念に対して，同じ操作停止を過負荷，低覚醒，深い思考，ツール待機へ分ける役割を EEG の必然性として書いた．

## 4. 社会的インパクトおよび社会実装アイデア

### 社会的インパクト

生成 AI の普及により，ナレッジワーカーの仕事は，単純な作業量ではなく，タスクに取り組む時刻，AI や他者の支援を使う場面，タスク分解の粒度が成果を左右するようになっている．一方で，ユーザは自分の認知負荷や集中の変化を正確に把握できない．

本提案は，個人に対して，自分が集中しやすい時間帯，停滞しやすいタスク粒度，中断要因，過負荷になりやすい作業条件を示す．組織に対しては，個人の認知状態を直接監視する用途を避け，本人が同意した範囲で作業設計や中断設計を改善する材料を提供する．

### 社会実装

第一段階では，個人向け PC アプリ又は VS Code/Notion 拡張として提供し，研究開発職，エンジニア，学生を対象に PoC を実施する．第二段階では，企業向けに，開発者生産性向上ツール，研究開発支援ツール，教育・学習支援ツールとして展開する．第三段階では，互換ハードウェア向け SDK や API を公開し，他社 EEG デバイスや既存タスク管理ツールとの連携を広げる．ただし，提案時点では間口を広げすぎず，初期市場を開発・研究系の知的作業支援へ絞る．

医療機器・SaMD としての訴求は初期市場から外し，健康診断，診断，治療ではなく，作業支援，セルフモニタリング，パフォーマンス最適化として位置づける．

### 市場規模

国内の専門的・技術的職業従事者は 2024 年に 1,324 万人であり，本提案はこの大規模な知的作業者層を長期的な対象とする．初期 SOM は，国内 IT 技術者・研究者等の約 150 万人を想定し，月額 2,000 円程度のソフトウェア課金とハードウェア買い切りを組み合わせて検証する．

SAM は，自社売上ではなく，認知状態に基づく集中最適化市場全体として，自社ソフト，自社ハード，互換ハード，作業ツール拡張，企業導入，SDK/API 連携を含めて定義する．自社だけで市場を制圧するのではなく，互換性のある他社ハードや既存業務ツールの拡張を成立させ，5 年後の市場規模を拡大する．

### コメントへの回答

- 社会実装は，個人向け PC アプリ又は VS Code/Notion 拡張から開始し，企業導入，互換ハードウェア向け SDK/API へ広げる段階計画にした．
- SAM は自社単独の売上ではなく，自社ソフト，自社ハード，互換ハード，作業ツール拡張，企業導入，SDK/API 連携を含む市場形成効果として整理した．
- 医療・診断・治療の市場は初期対象から外し，SaMD 認可を前提にしない記述へ統一した．

## 5. ソリューション研究開発およびアウトカム評価の実施計画

### 5.1 全体計画

1. 同期記録基盤の構築  
   EEG，操作ログ，作業ツール API/SDK，指定ウィンドウ録画を共通時刻へ同期する．

2. 状態推定と信号品質評価  
   認知負荷，課題関与，操作量，成果物差分を組み合わせ，作業状態を判定する．SEEG100E 等の基準計測系との比較，非人体評価，PSD 確認により，計測系の信頼性を評価する．

3. 作業レポートの実装  
   25 分ブロックを時系列で可視化し，停止イベント，画面文脈，成果物差分，判定理由を確認できる UI を作る．

4. Todo 更新機能の実装  
   高負荷で停滞したタスクを小さな単位へ分解し，ユーザ承認後に次回 Todo へ反映する．

5. PoC 評価  
   介入なし，作業レポートあり，作業レポートと Todo 更新ありの条件で，被験者内比較を実施する．

### コメントへの回答

- 実験スケジュールは II. 審査用資料の Month 1，Month 2-3，Month 4，Month 5-6 を正として，補足資料では同じ内容を機能別に説明する形へ整理した．
- PoC 評価条件は，介入なし，作業レポートあり，作業レポートと Todo 更新ありの 3 条件に統一した．
- 「パッと見て価値が分かる作業レポート」に開発リソースを集中する方針を，作業レポート実装を独立項目として置くことで反映した．

### 5.2 EEG 取得

作業中の認知負荷や課題関与の変化を捉えるため，頭皮上から非侵襲で EEG を取得する．前頭部，中心部，頭頂部を中心に計測し，初期評価では研究用途に適した多チャンネル構成から始め，寄与の大きい電極を特定した後，快適性を考慮してチャンネル数を絞る．

自作計測系は ADS1299 を用いた 8 チャネル構成を候補とする．必要に応じてデイジーチェーンによる拡張可能性を検討するが，NEDO 期間内の PoC では，実装負荷と装着性のバランスを重視する．

### コメントへの回答

- チャンネル数は，いきなり快適性重視の少数チャンネルに固定せず，初期評価では前頭部，中心部，頭頂部を含む多チャンネル寄りの構成から始め，寄与の大きい電極を特定してから絞る方針にした．
- ADS1299 の 8 チャネル構成を候補とし，デイジーチェーンは拡張可能性として残した．ただし NEDO 期間内の PoC では実装負荷と装着性を優先する．

### 5.3 操作量の算出

操作量は，キー入力数，マウス移動量，クリック数，スクロール量，アイドル時間，アプリ切替，対象ツール内の成果物更新から算出する．作業開始前又は過去の同種作業から通常操作量をベースラインとして記録し，ベースラインに対する相対値で高低を判定する．初期 PoC では，全アプリ横断の汎用取得にこだわらず，VS Code や Notion 等の対象ツールを絞り，実作業の中で評価できる範囲から始める．

### コメントへの回答

- 操作量指標は汎用的に定義しつつ，実装では対象ツールを絞る方針にした．これにより，審査上は一般性を示しながら，PoC の開発負荷を抑える．
- Notion，Jira，Office 365 などへの横展開は将来展開とし，最初は VS Code 又は Notion 等で実作業評価を完走できる範囲から始める．

### 5.4 認知負荷の算出

認知負荷は，前頭 theta パワーを主指標とし，前頭 theta と頭頂 alpha の対数差を補助指標とする．

```text
W_theta(t) = log(theta_frontal(t))
W_ratio(t) = log(theta_frontal(t)) - log(alpha_parietal(t))
```

ベースラインと比較して，認知負荷を低，適正，高の 3 段階に分ける．初期基準では，個人内 z 得点が -1 未満の区間を低負荷，-1 以上 +1 以下の区間を適正負荷，+1 超の区間を高負荷とする．N-back 課題と NASA-TLX，VAS を用いて，3 段階の境界値の個人内妥当性を確認する．

### 5.5 作業状態の判定

| 操作量 | 認知負荷 | 状態 | 支援方針 |
| --- | --- | --- | --- |
| 高 | 低又は適正 | 順調な集中 | 現状の Todo 方針を維持する |
| 高 | 高 | 高負荷な集中 | 作業単位を小さくする候補を提示する |
| 低 | 適正 | 低活動だが思考中 | 介入せず，思考区間として保護する |
| 低 | 高 | 高負荷で停滞 | 調査，確認，最初の一手に分解する |
| 低 | 低 | 作業からの離脱 | 休憩，低負荷タスク，着手しやすい行動を提案する |

読書，動画視聴，会議など，通常操作量が低いタスクでは，タスク種別ごとに比較基準を変更する．ただし，初期 PoC では対象タスクを絞り，状態分類の妥当性を優先して検証する．

### コメントへの回答

- タスク種別ごとの比較基準は必要だが，今回やりきることにこだわらないという指摘に沿い，初期 PoC では対象タスクを絞ると明記した．
- 状態分類は II. 審査用資料に合わせ，「順調な集中」「高負荷な集中」「高負荷で停滞」「低活動だが思考中」「作業からの離脱」の 5 状態で統一した．
- 低活動でも適正負荷の区間を「思考中」として保護し，操作停止を一律に介入対象にしない設計にした．

### 5.6 課題関与と同期度

課題関与は，beta / (alpha + theta) を用いて補助的に算出する．作業開始前のベースラインから 0 から 100 へ正規化し，0 から 30 を低，31 から 70 を中，71 から 100 を高とする方式を初期基準にする．課題関与は介入方法の選択や深い思考の保護に用いるが，単独で成果や集中力を断定しない．

dPLI 等の同期度指標は，リアルタイム介入の主判定には用いず，タスク種別と成果に関連する個人内パターンを探索する長期指標として扱う．同じタスク種別で再現した場合に限り，作業後レポートや次回 Todo 配置へ利用する．

### コメントへの回答

- 指標の式自体は維持しつつ，SEEG100E 等の基準計測系や予備実験で，帯域別 PSD とシステム固有の癖を事前に確認する計画を入れた．
- dPLI はリアルタイム介入の主判定には使わず，長期的な個人内パターンの探索指標に下げた．
- beta/(alpha+theta) のような比率指標も，ハードウェアの帯域応答を把握した上で解釈する方針にした．

### 5.7 作業レポート

作業レポートは，審査時に最も直感的に価値を示す機能として重点的に開発する．25 分ブロックについて，操作量，認知負荷，課題関与，キー入力，マウス操作，成果物差分，画面文脈を同じ時間軸上で可視化する．

画面上部には，操作量 2 段階と認知負荷 3 段階の各組合せについて，滞在時間と作業時間全体に占める割合を示す．時系列グラフには，認知負荷と操作量の推移を重ね，停止イベントをマーカとして示す．停止イベントを選択すると，その時点の画面，対象ファイル又はタスク，成果物差分，判定理由，次回 Todo 候補を並べて確認できる．

ユーザが長期間使い方を学ばなくても価値が伝わるよう，発生した状態変化，判定理由，次に取る行動を 1 画面で確認できる構成にする．

### コメントへの回答

- 作業レポートを審査時に最も直感的に価値を示す機能として位置づけ，重点開発対象にした．
- レポートの読み方をユーザが長期間学ぶ前提にせず，状態変化，判定理由，次に取る行動を 1 画面で確認できる UI として書いた．
- 「すごさ」が伝わる材料として，時間割合の集計，時系列グラフ，停止イベント，画面・成果物・判定理由の対応を明記した．

### 5.8 Todo 更新

作業開始前に，Todo ごとの確認可能な完了条件を設定する．完了条件は，成果物差分，テスト結果，文書更新，タスク状態などから判定する．

## 7. 本提案で取り扱う脳由来信号の説明

### 7.1 計測デバイス

本提案で扱う信号は，頭皮上電極で非侵襲に取得する EEG である．自作計測系として，EEG・生体電位計測用の 8 チャネル同時サンプリング 24 bit ADC である ADS1299 と，小型無線マイコン XIAO ESP32-S3 を用いた計測基板を候補とする．

本チームは，ADS1299 と XIAO ESP32-S3 を用いた計測基板，Ag/AgCl 電極，電極位置を変更できる装着筐体，BLE 計測アプリ，MNE-Python による解析基盤を試作した．同試作機では，アナログ電源とデジタル電源の分離，LDO レギュレータ，刺激時刻を記録するフォトダイオード入力を実装した．既存の生体信号アンプとの同時計測により，閉眼 alpha，ERP，SSVEP を確認しているが，定量的な信号品質評価は本提案で実施する．

評価では，SEEG100E 等の検査済み計測系を基準として用いる．人体計測に加え，信号発生器等を用いた非人体評価により，ノイズフロア，帯域別応答，電源ノイズ，入力段の安定性を確認する．これにより，性能の良否だけでなく，検査済み計測系との比較に基づく説明可能性を確保する．

### コメントへの回答

- SEEG100E の拠出コメントに対応し，検査済み計測系を基準として用いること，非人体評価を加えることを本文に入れた．
- 評価項目は，ノイズフロア，帯域別応答，電源ノイズ，入力段の安定性とし，人体計測だけに依存しない説明にした．
- 自作計測系は採用候補として扱い，定量的な信号品質評価は本提案で実施すると明記した．

### 7.2 信号品質管理

脳波に混入する可能性がある電極接触不良，まばたき，眼球運動，顔や首の筋活動，体動，電源由来雑音を検出する．前処理では，0.5 から 30 Hz のバンドパスフィルタと 50 Hz ノッチフィルタを全参加者へ共通して適用する．筋電図及び眼電図を必要に応じて記録し，アーチファクト区間の検出精度を高める．

ADS1299 の BIAS 帰還回路，入力段の RC フィルタ，デジタルフィルタ機能については，実装回路と評価結果に基づき，コモンモードノイズ対策として説明可能な範囲を追記する．結果に合わせて参加者ごとに恣意的に処理条件を変えず，除外基準を事前に定める．

### 7.3 指標の検証

本提案では，次の指標について，自作計測系と実作業環境における再現性及び個人内較正を確認する．

- 課題関与指標: beta / (alpha + theta)
- 認知負荷指標: 前頭 theta，前頭 theta と頭頂 alpha の対数差
- 低覚醒・疲労方向指標: (theta + alpha) / beta
- 前頭 alpha 非対称性: 探索的に本人の接近・回避自己報告との対応を見る
- dPLI: タスク種別及び成果による前頭部・頭頂部間の位相先行・遅延パターンを見る

先行研究で示された集団レベルの傾向をそのまま全利用者へ当てはめず，本人の基準値，課題操作への反応，日をまたぐ再現性を確認してから利用する．

### 実装した各機能とその実現方法（1）：作業ツール・入力データの取得

チームは `eeg-task-scheduler` として，本提案が必要とする各機能を実際に動くアプリケーションとして実装した．どの機能をどの API・仕組みで実現したかは次の通りである．

a) タスク管理アプリ（Notion）との連携方法

Notion 側で Internal Integration を作成し，発行された API トークンと，Todo を管理する Tasks データソースの ID を設定する運用にした．バックエンドは Notion の REST API（データソースへの `query`，`pages` の作成・更新，`comments` の追加）を `httpx` で直接呼び出す形で実装している．未完了 Todo は `Status` プロパティが完了系でないページを取得して一覧化し，セッション開始時には選択された Todo ページの `Status` を `In Progress` に更新する．セッション終了後は，生成した次 Todo 候補を新しい Notion ページとして作成し，元の Todo ページには作業レポートの要約をコメントとして追加する．これにより，計測結果がアプリの中だけで完結せず，ユーザが普段使っている Notion のタスク一覧に直接反映される．

b) アクティブウィンドウ・キー/マウス入力の取得方法

VS Code や Notion といった個々のツールの拡張機能を先に作り込むのではなく，Windows の OS レベル API を Electron のメインプロセスから呼び出す方法で作業内容の外形を取得している．前面ウィンドウの取得は，Electron から PowerShell 経由で Win32 API の `GetForegroundWindow` と `GetWindowText` を呼び出し，作業中のアプリ名・ウィンドウタイトルを取得する．キーボード・マウス入力は，同じく PowerShell 上で C# コードを動的にコンパイルし，`SetWindowsHookEx` によるグローバルフック（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`）を仕掛けて，キー押下数，クリック数，スクロール数，マウス移動距離をバックグラウンドで常時カウントする．この値は Electron の `contextBridge` を介して React 側の画面へ安全に公開し，React 側が 30 秒ごとに差分を取得してバックエンドへ送信する．この構成にすることで，対象アプリを個別に拡張しなくても，PC 上のあらゆる作業に対して同じ形式で操作量を計測できる．

c) 画面キャプチャと画面文脈の補完方法（VLM）

画面情報の取得は，Electron の `desktopCapturer` API でユーザが選択したウィンドウ／画面のスクリーンショットを取得し，バックエンドへ base64 の PNG として送信する形にした．バックエンドはこの画像を Google Gemini のマルチモーダル生成 API（`generate_content` に画像を `inline_data` として渡す呼び出し）に送り，「現在の Todo との関係が分かるように，作業内容を日本語で要約せよ」という指示とあわせて画面の説明文を生成させている．Todo や操作量のように API/SDK から構造化データとして取得できるものはそのまま使い，画面の意味づけという構造化しにくい部分だけを VLM に任せる役割分担にすることで，画面全体を独自に解析する重い処理を避けている．

### 実装した各機能とその実現方法（2）：EEG計測・状態判定・レポート生成

a) EEG デバイスとの通信方法

自作 EEG デバイス（ADS1299 + ESP32-S3）とは Bluetooth Low Energy（BLE）の Nordic UART Service（NUS）で通信している．PC 側は Python の BLE ライブラリ `bleak` でデバイスをスキャン・接続し，NUS の通知キャラクタリスティックを購読して EEG サンプルをストリーミング受信する一方，書き込みキャラクタリスティックにコマンドバイトを送ることでストリーミングの開始・停止を制御している．受信したバイト列は，チームが独自に定義したパケット形式（サンプル番号と 8 チャンネル分の生値）に従って逐次パースし，EEG 特徴量計算モジュールへ渡している．

b) EEG 特徴量の計算方法

受信した生波形は，脳波解析の標準ツールである MNE-Python に読み込ませ，Welch 法によるパワースペクトル密度計算（`psd_array_welch`）で周波数成分に分解する．そこから theta（4–7 Hz），alpha（8–12 Hz），beta（13–30 Hz）帯域のパワーを積分し，課題関与指標（beta / (alpha + theta)）と認知負荷指標（theta / alpha）を算出する．この計算を 10 秒窓・5 秒ステップで繰り返すことで，作業中の認知状態をほぼリアルタイムに更新し続ける仕組みを実現した．

c) 作業状態の判定方法

EEG 由来の認知負荷指標と，前述のキー・マウス操作量を掛け合わせ，「操作量が多く負荷が高くない＝フロー」「操作量が少なく負荷が高い＝過負荷停止」「操作量が少なく関与が低い＝逸脱停止」といった条件分岐で状態ラベルを決定している．判定結果は，同じ時刻の画面文脈の要約とあわせて 30 秒単位の「エピソード」としてデータベースに記録し，作業レポート画面で時系列に表示している．

d) 作業レポート・次 Todo 候補の生成方法

セッション終了時には，記録済みのエピソード（作業状態，画面文脈，操作量の時系列）を Gemini のテキスト生成 API に渡し，「25 分の作業を振り返り，次に行うべき Todo を最大 3 つ提案せよ」という指示で要約と Todo 候補を生成させている．過去のエピソードやレポートは埋め込みベクトルとして Chroma（ベクトル DB）に蓄積しており，類似する過去の作業記録を検索して要約生成のプロンプトに含めることで，単発のセッションだけでなく過去の作業傾向も踏まえた提案を行う RAG（Retrieval-Augmented Generation）構成にしている．生成された次 Todo 候補は，ユーザが確認・承認した場合のみ（a）で述べた Notion 連携を通じて書き戻される．

### 研究開発実績

東京農工大学「2025 年度 学生プロジェクト」に採択されたプロジェクト「モジュール式生体信号計測デバイスの開発」では，脳波計測装置，電極，装着筐体，ファームウェア，モバイルアプリ，解析ソフトウェア，サーバを実装した．

- ADS1299 及び ESP32-S3 を用いた BLE 接続可能なワイヤレス計測基板
- Ag/AgCl とシリコンを組み合わせた長時間計測可能な電極
- 10-20 法上で電極位置を変更可能な 3D プリント筐体
- BLE 受信，リアルタイム描画，サーバ接続を担うモバイルアプリ
- データ蓄積，BIDS 形式エクスポート，RSVP 非同期解析，MNE-Python による解析基盤を備えるサーバ

既存の生体信号アンプとの閉眼 alpha，ERP，SSVEP の同時計測は実施済みである．同プロジェクトの成果は，東京農工大学と国立精神・神経医療研究センターの合同シンポジウムでポスター発表及び計測体験として報告した．一方，信号対雑音比，帯域パワー相関，ERP 振幅・潜時，SSVEP ピーク，試行間再現性などの定量評価は本提案で実施する．
